# Discord 絵文字・スタンプ棚卸し Bot

現在そのDiscordサーバーに登録されているカスタム絵文字・スタンプの使用状況を調べ、削除を検討する候補を表示するBotです。

Discord上で使うコマンドは `/scan` だけです。コマンドにオプションを付ける必要はありません。

## 使い方

1. Botをサーバーへ招待する
2. Botに対象チャンネルの閲覧権限とメッセージ履歴の閲覧権限があることを確認する
3. `Manage Server` 権限を持つ人が `/scan` を実行する
4. 走査中は同じ進捗メッセージが更新され、完了時に削除候補の結果が新しいメッセージで投稿される

走査中に一時的な取得失敗が起きた場合は、Botが再試行します。権限不足や削除済みチャンネルなど、どうしても取得できない場所は対象外にして、取得できる範囲をすべて調べた時点で完了します。

`/scan` は、実行時点でDiscordから取得できる履歴を使って統計を再構築するスナップショットです。再スキャンすると、それ以前の日次集計は引き継がれず、削除済みメッセージなど取得できなくなった履歴は結果から外れます。Bot導入後にリアルタイムで観測した値も、再スキャン時には履歴から再計算されます。削除判断には、走査状態と取得失敗件数も確認してください。

## 表示される内容

進捗メッセージには次の内容だけが表示されます。

```text
削除候補を調査中
履歴取得中
処理済み: メッセージ 5385件 / チャンネル 23件 / スレッド 5件
集計件数: 本文絵文字 10件 / スタンプ 24件 / リアクション 33件

現在の使用数上位5（直近30日）
<:emoji_name:123456789012345678> emoji_name — 58件 / 累計420件
welcome — 18件 / 累計90件

削除候補・使用数下位5
unused — 0件 / 累計0件
```

絵文字は実際の絵文字として表示されます。スタンプは名称と画像で表示されます。

完了後は、削除をおすすめする絵文字・スタンプだけが表示されます。Botが自動で削除・改名することはありません。

## 集計の対象

- メッセージ本文で使われたカスタム絵文字
- スタンプとして送信された回数
- リアクションとして残っているカスタム絵文字
- Bot導入後に観測した本文・スタンプ・リアクションの利用

Bot自身が送信したメッセージ、編集、リアクションは利用実績に数えません。

初回走査の過去リアクションは、実際に押された日時ではなく、そのリアクションが残っている投稿の日付に集計する近似です。

対象は現在そのサーバーに登録されているカスタム絵文字・スタンプです。Unicode絵文字、他サーバー由来の絵文字・スタンプ、すでに削除された資産は対象外です。

## 権限とプライバシー

Botに必要な権限は次のとおりです。

- View Channel
- Read Message History
- Send Messages
- Embed Links

Administrator、絵文字管理、スタンプ管理の権限は不要です。

Botは会話本文や発言者ランキングを保存せず、走査中に本文を解析して使用回数だけを集計します。削除済みメッセージ、解除済みリアクション、編集前の本文など、Discord APIから復元できない情報は推測で補完しません。

## Debianサーバーに保存されるデータ

Botの保存先は環境変数 `DATA_DIR` です。Debian LXCの標準構成では `/var/lib/discord-emoji-audit` です。

### 継続的に保存されるもの

- 日付ごとの使用回数
  - 本文中のカスタム絵文字
  - スタンプ送信
  - 正確に観測したリアクション追加
  - 初回走査で投稿日に帰属したリアクション近似値
  - 編集差分不明、リアクション解除の観測数
- 現在の絵文字・スタンプのID、種類、現在の名前、名前の観測履歴、現在登録中かどうか
- スタンプ画像を表示するためのCDN URL
- 管理者が確認した絵文字・スタンプ系列の対応。手動対応付けを使った場合は確認日時、確認者ID、メモ
- 走査状態、対象サーバーID、対象チャンネル・スレッドID、進捗メッセージID、走査実行者ID、エラー内容などの運用メタデータ

使用回数は現在のスナップショットの日付と絵文字・スタンプのIDに紐づけて保存され、通常は自動削除されません。再スキャンで日次集計は置き換わります。

### 一時的または障害時に残るもの

- `audit.json.bak`: `audit.json`の直前バックアップ
- `scan-<guildId>-<runId>.json`: 初期走査の再開用チェックポイント。正常完了時に削除
- `scan-live-<guildId>.jsonl`: 走査中に発生した未反映イベント。正常反映後に削除
- `*.orphan`: 前回走査の未反映イベントを退避したもの。自動で即時削除せず、運用者が確認・整理する
- ロックファイル: BotプロセスのPIDのみ
- systemdのジャーナル: ログイン、APIエラー、再試行、バックアップ先などの運用ログ

未反映イベントの一時ファイルには、使用対象のID・名前・イベント種別・回数・観測日時と、重複判定用の投稿作成日時が含まれます。元メッセージIDはこの一時ファイルへ保存する前に除去されます。

## 保存されないデータ

- メッセージ本文そのもの
- メッセージ本文を解析した全文や抜粋
- 発言者のユーザーID、ユーザー名、発言者別ランキング
- リアクションを押した人のユーザーID
- メッセージごとの絵文字使用履歴や、絵文字を使ったメッセージのURL
- 削除済みメッセージの内容、解除済みリアクションの過去日時、編集前本文

ただし、走査の再開・進捗表示に必要なBot自身の進捗メッセージID、走査実行者ID、チャンネルIDなどの運用情報は保存されます。また、手動で系列を確認した場合は確認者IDが保存されます。これは発言者やリアクション利用者の分析には使用しません。

Discord APIの応答には作成者などのメッセージメタデータが含まれる場合がありますが、Botはそれを集計対象として保存しません。初期走査で取得した過去メッセージは、Botプロセスのメモリ上で解析した後、本文を破棄します。過去メッセージを全文保存する外部サービスへの送信は行いません。

## Discordとの送受信

### Discordから受信するもの

- サーバー、チャンネル、スレッドの一覧とID・名前・権限エラー
- 現在登録されているカスタム絵文字・スタンプのID、名前、状態、スタンプ画像URL
- 初期走査対象のメッセージ履歴。本文、作成日時、スタンプ、残っているリアクション数を解析に使用
- 導入後の新規メッセージ、メッセージ編集、リアクション追加・解除、絵文字・スタンプの追加・削除・改名イベント

### Discordへ送信するもの

- `/scan`の登録と実行応答
- 実行者へのメンション付き進捗メッセージの作成・編集・削除
- 処理済み件数、集計件数、絵文字の実物表示、スタンプ名・画像、削除推奨候補、ランキング
- APIへ返すための通常の認証情報と、Discord APIが要求するリクエスト情報

メッセージ履歴の本文や発言者情報を、Discord以外の外部サービス、生成AI、アクセス解析サービスへ送信する処理はありません。

### 取得範囲の注意

- private archived thread の全件取得には `Manage Threads` が必要です。Botは最小権限を維持するためこの権限を要求せず、取得できないprivate archived threadは対象外になる場合があります。
- 音声チャンネル内のテキストチャットは、Discordの仕様上 `Connect` 権限が必要になる場合があります。Botは `Connect` を要求しないため、対象外になる場合があります。
- 権限不足や削除済み範囲はエラーとして記録してスキップします。完了結果は取得できた範囲だけの集計です。

## 招待URLの作成

Developer PortalのApplication IDを使って、次のURLを作成できます。

```text
https://discord.com/oauth2/authorize?client_id=アプリケーションID&permissions=84992&scope=bot%20applications.commands
```

Botの管理・更新・障害対応は運用者が行います。プログラム管理者向けの手順は [OPERATIONS.md](OPERATIONS.md) を参照してください。
