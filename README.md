# Discord 絵文字・スタンプ棚卸し Bot

現在そのDiscordサーバーに登録されているカスタム絵文字・スタンプの使用状況を調べ、ランキングを表示するBotです。

Discord上では `/scan`、`/report`、`/archive` を使います。全チャンネルを走査する場合は `/scan`、対象を指定する場合は `/scan channels:<チャンネルIDまたはメンション>` を使います。過去N日だけを走査する場合は `/scan days:N` を使います（Nは1以上の整数）。`/report` はスキャンせず、直近の完了結果をExcelファイルで出力します。`/archive` は画像をZIP形式で出力します。

## 使い方

1. Botをサーバーへ招待する
2. Botに対象チャンネルの閲覧権限、メッセージ履歴の閲覧権限、接続権限があることを確認する
3. 管理者、Bot所有者、または指定運用者が `/scan` を実行する（`/report` は全員が実行可能）
4. 走査中は同じ進捗メッセージが更新され、完了時に直近30日の上位・下位を短く投稿する
5. 詳細を確認したい場合は `/report` を実行し、添付された `emoji-audit-YYYY-MM-DD.xlsx` を開く

## 絵文字・スタンプの画像アーカイブ

`/archive` は次の画像・アニメーションをZIPにまとめ、Discordからダウンロードできるようにします。実行権限は `/scan` と同じ（サーバー管理者、Bot所有者、指定運用者）で、結果は初期設定では実行者にだけ表示されます。

- 現在登録されている絵文字・スタンプ（管理対象の絵文字を含む）
- 以前このサーバーに登録されていたとBotが認識している素材
- メッセージ本文・リアクション・スタンプ送信の履歴から見つけたID（他サーバー由来・削除済みの可能性があるもの）

使い方:

- `/archive`: 全候補の1ページ目をZIPで取得する
- `/archive page:2`: 次の50件を取得する。対象が多い場合は各ページを順に実行する
- `/archive scope:current`: 現在登録中の素材のみ（50件ずつ）
- `/archive scope:history`: 現在の登録対象外となった素材のみ（50件ずつ）
- `/archive only_me:false`: 結果をチャンネルに表示する（既定は非公開）

画像を取得すると、Botは `DATA_DIR/archive/<サーバーID>/<種別>/<ID>.<拡張子>` に元データを保存します。新規スキャンやリアルタイムの利用イベントでも、見つけた画像をバックグラウンドで取得して保存します。以降はCDN側で画像が削除されても、Botの保存済みコピーをZIPに含められます。`/scan` を再実行しても保存済み画像や発見済みIDは消しません。

ZIPには素材の画像と `manifest.json`（ID、名前、現在/旧登録/履歴のみの区分、ファイル形式、取得失敗理由）を収録します。Discordの添付ファイル容量制限を超える場合は、複数の独立したZIPに分割します。保存済み画像を含むため、`DATA_DIR/archive` も必ずバックアップ対象にしてください。

**復元可能性の限界:** 削除済みの素材がDiscordのCDNから取得できず、Botに保存済みの画像もなければ、IDや名前が分かっていても画像は復元できません。既存の旧版スキャンでは外部素材のIDを基本的に保存していないため、新しい版で `/scan` を再実行する必要があります。履歴だけで見つかったIDが自サーバー由来か他サーバー由来かは断定できません。削除済みメッセージや取得権限のないチャンネルの履歴は取得できません。

絵文字はDiscordが配信する128×128相当のWebP（動くものはアニメーションWebP）を優先し、必要に応じてGIF・PNGを試します。スタンプはPNG/APNG、GIF、Lottie JSONの元のアニメーション形式を維持します。元のアップロード形式や削除前の原本を必ず取得できるわけではありません。取得済み画像の再配布時は権利者・利用規約に注意してください。

走査中に一時的な取得失敗が起きた場合は、Botが最大10回再試行します。権限不足・取得不能・再試行上限到達のチャンネルは対象外にし、結果を「部分完了」として明示します。

`/scan` は、実行時点でDiscordから取得できる履歴を使って統計を再構築するスナップショットです。再スキャンすると、それ以前の日次集計は引き継がれず、取得できなくなった履歴は結果から外れます。Bot導入後にリアルタイムで観測した値も、再スキャン時には履歴から再計算されます。利用状況を判断するときは、走査状態と取得失敗件数も確認してください。

## 表示される内容

進捗メッセージには次の内容だけが表示されます。

```text
使用状況を調査中
履歴取得中
処理済み: メッセージ 5385件 / チャンネル 23件 / スレッド 5件
集計件数: 絵文字: 本文 10件 / リアクション 33件
集計件数: スタンプ: 24件

指定範囲合算
絵文字
使用数上位10（直近30日）
<:emoji_name:123456789012345678> emoji_name — 58件
welcome — 18件

使用数下位10（直近30日）
unused — 0件

使用数上位10（累計）
<:emoji_name:123456789012345678> emoji_name — 420件

使用数下位10（累計）
unused — 0件

平均使用頻度上位10
<:emoji_name:123456789012345678> emoji_name — 1.25件/日

スタンプ
使用数上位10（直近30日）
wave — 12件
```

絵文字は実際の絵文字として表示されます。スタンプは名称と画像で表示されます。

完了後は指定範囲全体の合算ランキングに加えて、走査対象チャンネルごとのランキングも表示されます。ランキングは絵文字、スタンプの順に分かれ、最近30日の使用数、累計使用数、平均使用頻度（累計使用数を資産IDの作成日時からの経過日数で割った値）について、上位10件・下位10件を表示します。同じ資産が上位・下位で重なる場合は一度だけ表示します。ID差し替えを確認済みの系列は、最も古いIDの作成日時を使います。`days:N` 指定時は過去N日の記録だけを再走査し、表示は「過去N日の使用数」「過去N日の使用日数」として扱い、累計列・累計ランキング・資産作成日基準の平均使用頻度・観測範囲を超える未使用判定を含めません。取得不能または探索失敗がある場合は、使用状況の判定欄を「判定保留」に統一します。該当する資産がない種類の見出しは表示しません。Botが資産を自動で消去・改名することはありません。

## 集計の対象

`/scan` には次の任意オプションがあります。

- `limit:15`: 上位・下位を15位まで表示する。15位が同率なら同率の資産をすべて表示する（省略時は10位）
- `channels`: 対象チャンネルIDまたはチャンネルメンションをカンマ区切りで複数指定する。省略時は全チャンネルを対象にし、指定チャンネルのスレッドも含める。`/report channels:<同じ指定>` で保存済み結果をExcel出力する
- `exclude_bots:true`: Botが送信したメッセージと、そのメッセージに残るリアクションを除外する
- `exclude_channels`: 除外するチャンネルIDまたはチャンネルメンションをカンマ区切りで複数指定する（指定チャンネルのスレッドも除外）
- `only_me:true`: 進捗と完了・失敗報告を実行者だけに表示する。`/report only_me:true` で結果だけを非公開表示できる

`/report` のExcelは、次の6シートで構成します。`04_要確認候補` は概要の直後に置き、全件一覧より先に確認できます。

- `00_概要`: 条件・件数・注意事項
- `04_要確認候補`: 未使用・低使用・命名規則外などの参考候補。管理者判断欄は空欄
- `01_絵文字棚卸し` / `02_スタンプ棚卸し`: 画像・利用状況・参考状態・判定を含む全件一覧
- `03_チャンネル別`: 本文・リアクション・スタンプ別の縦持ち使用明細
- `05_取得状況`: 取得不能チャンネル、未反映イベント、探索時エラー

`要確認` は削除指示ではありません。季節・イベント用途などを管理者が判断してください。

- メッセージ本文で使われたカスタム絵文字
- スタンプとして送信された回数
- リアクションとして残っているカスタム絵文字
- Bot導入後に観測した本文・スタンプ・リアクションの利用

Bot自身が送信したメッセージ、編集、リアクションは常に利用実績に数えません。`exclude_bots:true` を指定した場合は、他のBotが送信したメッセージと編集も除外します。履歴走査ではDiscordからリアクター一覧を取得しないため、他Botの既存リアクションは区別できません。

走査で取得した過去リアクションは、実際に押された日時ではなく、そのリアクションが残っている投稿の日付に集計する近似です。Bot稼働中に追加されたリアクションは、追加イベントの日時で集計します。

対象は現在そのサーバーに登録されているカスタム絵文字・スタンプです。Unicode絵文字、他サーバー由来の絵文字・スタンプ、すでに登録解除された資産は対象外です。

## 権限とプライバシー

Botに必要な権限は次のとおりです。

- View Channel
- Read Message History
- Send Messages
- Embed Links
- Connect

Administrator、絵文字管理、スタンプ管理の権限は不要です。

`/scan` はサーバー管理者、Discord ApplicationのBot所有者、または環境変数`BOT_OWNER_USER_IDS`に指定したユーザーだけが実行できます。指定運用者`363466015683903488`は常に許可されます。`BOT_OWNER_USER_IDS`はカンマ区切りのDiscordユーザーIDです。完了後5分間は次の`/scan`を開始できません。

Botは会話本文や発言者ランキングを保存せず、走査中に本文を解析して使用回数だけを集計します。取得できないメッセージ、解除済みリアクション、編集前の本文など、Discord APIから復元できない情報は推測で補完しません。

## Debianサーバーに保存されるデータ

Botの保存先は環境変数 `DATA_DIR` です。Debian LXCの標準構成では `/var/lib/discord-emoji-audit` です。

### 継続的に保存されるもの

- 日付ごとの使用回数
  - 本文中のカスタム絵文字
  - スタンプ送信
  - 正確に観測したリアクション追加
  - 走査時に投稿日へ帰属したリアクション近似値
  - 編集差分不明、リアクション解除の観測数
- 現在の絵文字・スタンプのID、種類、現在の名前、名前の観測履歴、現在登録中かどうか
- スタンプ画像を表示するためのCDN URL
- 走査状態、対象サーバーID、対象チャンネル・スレッドID、進捗メッセージID、走査実行者ID、エラー内容などの運用メタデータ

使用回数は現在のスナップショットの日付と絵文字・スタンプのIDに紐づけて保存され、通常は自動で消去しません。再スキャンで日次集計は置き換わります。

### 一時的または障害時に残るもの

- `audit.json.bak`: `audit.json`の直前バックアップ
- `scan-<guildId>-<runId>.json`: 走査の再開用チェックポイント。正常完了時に消去
- `scan-live-<guildId>.jsonl`: 走査中に発生した未反映イベント。正常反映後に消去
- `channelDaily`: 全チャンネル走査で作成したチャンネル別の日次集計
- `scopeReports`: 対象チャンネル範囲ごとの最新スナップショット
- `*.orphan`: 前回走査の未反映イベントを退避したもの。自動で即時消去せず、運用者が確認・整理する
- ロックファイル: BotプロセスのPIDのみ
- systemdのジャーナル: ログイン、APIエラー、再試行、バックアップ先などの運用ログ

未反映イベントの一時ファイルには、使用対象のID・名前・イベント種別・回数・観測日時と、重複判定用の投稿作成日時が含まれます。元メッセージIDはこの一時ファイルへ保存する前に除去されます。

## 保存されないデータ

- メッセージ本文そのもの
- メッセージ本文を解析した全文や抜粋
- 発言者のユーザーID、ユーザー名、発言者別ランキング
- リアクションを押した人のユーザーID
- メッセージごとの絵文字使用履歴や、絵文字を使ったメッセージのURL
- 取得できないメッセージの内容、解除済みリアクションの過去日時、編集前本文

ただし、走査の再開・進捗表示に必要なBot自身の進捗メッセージID、走査実行者ID、チャンネルIDなどの運用情報は保存されます。これは発言者やリアクション利用者の分析には使用しません。

Discord APIの応答には作成者などのメッセージメタデータが含まれる場合がありますが、Botはそれを集計対象として保存しません。走査で取得した過去メッセージは、Botプロセスのメモリ上で解析した後、本文を破棄します。過去メッセージを全文保存する外部サービスへの送信は行いません。

## Discordとの送受信

### Discordから受信するもの

- サーバー、チャンネル、スレッドの一覧とID・名前・権限エラー
- 現在登録されているカスタム絵文字・スタンプのID、名前、状態、スタンプ画像URL
- `/scan` の走査対象メッセージ履歴。本文、作成日時、スタンプ、残っているリアクション数を解析に使用
- 導入後の新規メッセージ、メッセージ編集、リアクション追加・解除、絵文字・スタンプの追加・除去・改名イベント

### Discordへ送信するもの

- `/scan`の登録と実行応答
- 実行者へのメンション付き進捗メッセージの作成・編集・整理
- 処理済み件数、集計件数、絵文字の実物表示、スタンプ名・画像、使用状況ランキング
- APIへ返すための通常の認証情報と、Discord APIが要求するリクエスト情報

メッセージ履歴の本文や発言者情報を、Discord以外の外部サービス、生成AI、アクセス解析サービスへ送信する処理はありません。

### 取得範囲の注意

- private archived thread の全件取得には `Manage Threads` が必要です。Botは最小権限を維持するためこの権限を要求せず、取得できないprivate archived threadは対象外になる場合があります。
- 音声チャンネル内のテキストチャットも走査対象です。対象チャンネルの閲覧権限、メッセージ履歴の閲覧権限、`Connect` 権限が必要です。
- 権限不足や取得不能範囲はエラーとして記録してスキップします。完了結果は取得できた範囲だけの集計です。

## 招待URLの作成

Developer PortalのApplication IDを使って、次のURLを作成できます。

```text
https://discord.com/oauth2/authorize?client_id=アプリケーションID&permissions=1133568&scope=bot%20applications.commands
```

Botの管理・更新・障害対応は運用者が行います。プログラム管理者向けの手順は [OPERATIONS.md](OPERATIONS.md) を参照してください。
